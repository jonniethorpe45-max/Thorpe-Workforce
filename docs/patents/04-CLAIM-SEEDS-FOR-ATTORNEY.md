## Patent A — Core orchestration

### Independent claim 1 (system — seed)

A computer system comprising at least one processor and memory storing instructions that, when executed, cause the system to:

**(a)** receive, at a local client device, a natural-language user message describing a computing device problem;

**(b)** collect local system evidence from the client device, the local system evidence including at least one of operating system state, resource utilization, or network state;

**(c)** generate a repair plan comprising a plurality of repair action identifiers selected from a catalog of repair actions, wherein generating the repair plan comprises applying at least one of a rule-based planner or a language model that outputs a structured plan;

**(d)** filter the repair plan by intersecting the repair action identifiers with an allowlist of permitted repair actions;

**(e)** automatically execute, on the client device without user interaction, repair actions classified as non-mutating diagnostics;

**(f)** defer execution of repair actions classified as mutating until receipt of user confirmation;

**(g)** after successful execution of at least one mutating repair action, perform a follow-up system health scan and compute a verification metric comparing health before and after execution;

**(h)** generate a user-facing narrative describing repairs executed in step (e) and optionally step (f), wherein the narrative is constrained to repairs having recorded execution results; and

**(i)** present, in a single user interface response, the narrative, the recorded execution results, any deferred repair actions, and the verification metric.

### Independent claim 2 (method — seed)

A computer-implemented method performed on a client device, comprising: [mirror steps (a)–(i) from claim 1 in method form].

### Dependent claims (seeds — select and refine)

3. The system of claim 1, wherein generating the repair plan comprises calling a first language model to produce a JSON-structured plan and, upon failure of the first language model, falling back to a rule-based planner mapping keywords in the user message to repair action identifiers.

4. The system of claim 1, wherein generating the user-facing narrative comprises calling a second language model separate from the first language model used to generate the repair plan.

5. The system of claim 1, wherein the allowlist is derived from cryptographically signed repair pack manifests installed on the client device.

6. The system of claim 1, further comprising, prior to step (c), detecting security-sensitive keywords in the user message and, upon detection, creating a support case record and skipping steps (e) and (f).

7. The system of claim 1, further comprising, prior to step (c), upon detecting network-related keywords, executing an offline connectivity diagnostic suite without cloud network access and storing results as session evidence.

8. The system of claim 7, further comprising removing a connectivity diagnostic repair action identifier from the repair plan when the offline connectivity diagnostic suite was already executed for the session.

9. The system of claim 1, wherein the user-facing narrative is generated by a local template formatter when a cloud language model is unavailable.

10. The system of claim 1, wherein the single user interface response includes structured metadata persisted to enable restoration of repair results and agent plan upon session reload.

## Patent B — Repair packs

### Independent claim (seed)

A method for controlling autonomous operating-system repair tool execution on a client device, comprising:

receiving a repair pack manifest specifying a plurality of repair tools and a digital signature;

verifying the digital signature using a public key embedded in a client application;

upon successful verification, storing the repair pack and enabling the repair tools in an allowlist;

receiving a planned set of repair tool identifiers from an AI planning module; and

executing only those planned repair tool identifiers present in the allowlist.

### Dependent claims (seeds)

- wherein the digital signature is an Ed25519 signature over canonical JSON of the manifest
- wherein built-in repair packs are non-overwritable by custom packs
- wherein each repair tool maps to a canonical repair action identifier in a global catalog

## Patent C — Offline connectivity

### Independent claim (seed)

A computer-implemented method for offline network diagnostics in an AI-assisted support application, comprising:

detecting, from a user message, network connectivity intent;

executing, without requiring internet connectivity to a cloud AI service, a layered connectivity suite comprising adapter status, gateway reachability, domain name resolution, and internet endpoint reachability checks;

evaluating check results with a local decision tree to produce recommended repair action identifiers and a playbook summary;

persisting the connectivity results as evidence linked to an agent session;

generating a repair plan for the user message;

removing a duplicate connectivity diagnostic identifier from the repair plan when the layered connectivity suite was executed; and

including the connectivity results in a chat response to the user.

## Patent D — Watchdog handoff

### Independent claim (seed)

A method for proactive system monitoring integrated with a conversational repair agent, comprising:

periodically scanning, by a background monitor on a client device, system health metrics including at least CPU utilization, memory utilization, and storage utilization;

generating an alert when a metric exceeds a corresponding threshold;

optionally pre-computing a repair plan for the alert using a rule-based planner;

notifying a user of the alert;

in response to user selection of a handoff action, injecting a synthetic support request into a conversational agent pipeline that executes the same incident orchestration process used for interactive chat, including local repair execution and narrative generation; and

acknowledging the alert upon successful completion of the incident orchestration.

### Dependent claims (seeds)

- wherein alerts are deduplicated per alert type within a configurable time window
- wherein the pre-computed repair plan is merged into an agent response when a cloud planner is unavailable

## Patent E — Dual LLM

### Independent claim (seed)

A system comprising a client device configured to:

invoke a first language model to produce a structured repair plan in machine-readable format;

filter plan steps to an allowlist of repair tools;

execute permitted repair tools on the client device;

invoke a second language model, independent of the first language model, to generate a natural-language summary constrained to describe only repair tools already executed; and

upon failure of either language model, fall back to a respective non-LLM alternative selected from rule-based planning or template-based narration.

## Patent F — Security gate

### Independent claim (seed)

A method comprising: receiving a user message at an autonomous IT repair agent; classifying the message as a security escalation based on keyword detection for at least one of malware indicators or credential-related terms; in response to classification as security escalation, creating a support case, transmitting a webhook notification to an external professional services automation system, and inhibiting execution of automated repair actions; and returning an escalation identifier to a user interface without performing mutating repairs.
